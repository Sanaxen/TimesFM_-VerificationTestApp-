# TimesFM 時系列予測アプリ

[日本語](README_ja.md) |[English](README.md)

Google Research の時系列基盤モデル **TimesFM 2.5（200M）** を使った、Windows 向けのローカル時系列予測アプリです。
UI は Streamlit で、ブラウザ上で CSV の読み込みから予測、グラフ表示までを行えます。

## 動作環境

- Windows 10 / 11
- Python 3.10 以上（PATH に通っていること）
- インターネット接続（初回の予測時に、モデル `google/timesfm-2.5-200m-pytorch` を Hugging Face から自動ダウンロードします）

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `setup.bat` | 仮想環境（`venv`）の作成とライブラリのインストール |
| `run.bat` | アプリの起動（`venv` が無ければ先に `setup.bat` を実行） |
| `app.py` | アプリ本体 |
| `requirements.txt` | 必須ライブラリの一覧 |
| `sample.csv` | 動作確認用のサンプルデータ（時間単位、2項目） |
| `settings.json` | 「アプリのフォルダに保存」を押したときに作られる設定ファイル |

## セットアップと起動

1. フォルダ一式を任意の場所に置きます（`Downloads` 以外を推奨。後述のトラブルシューティング参照）。
2. `setup.bat` をダブルクリックします。
   - `venv` を作成し、`requirements.txt` の内容をインストールします。
   - 続けて、共変量用の `timesfm[xreg]`（JAX を使用）を別枠でインストールします。失敗しても警告が出るだけで、共変量なしの予測や Ridge 方式の共変量は使えます。
3. `run.bat` をダブルクリックすると、ブラウザでアプリが開きます。

## 使い方

1. **CSV を選択**します（文字コードは UTF-8 / Shift-JIS、区切り文字はカンマ・セミコロン・タブを自動判別）。
2. **日時・時間の項目**と、**予測するデータ項目**（複数選択可）を選びます。
3. **検証期間**（データ全体の後半何 % か）と**予測期間**（末尾から先の行数）を指定します。
4. 必要に応じて、**TimesFM の予測パラメータ**と**説明変数（共変量）**を設定します（初期値はデフォルト）。
5. **予測開始**を押すと、グラフに結果が追加されます。

### 検証と予測の仕組み

- **検証予測**（点線）: 検証期間より前のデータだけを使って検証期間を予測し、実測との差を MAE / RMSE / MAPE で表示します。
- **未来予測**（破線）: 全データを使って、末尾から先を予測します。

この2本は別々の予測なので、検証予測の終点と実測の末尾には、予測誤差ぶんの段差が出ます。

**「検証区間の開始点から予測を開始する」をオンにした場合**

- 検証期間より前のデータだけを使い、検証期間の先頭から「検証期間＋予測期間」ぶんを1回で予測します。
- 検証予測と未来予測が1本につながり、上記の段差は出ません。
- 一方で、検証期間の実測値は予測に使われないため、直近の動きは反映されません。
- 検証期間が 0% のときは無効です。

### グラフ

- 予測項目ごとに色分けして表示します。検証期間は橙、未来予測の区間は緑の背景で示します。
- 「表示切り替え」で、全体表示と「検証・予測区間のみ」を切り替えられます。
- 「項目ごとにグラフを分ける」で、スケールの違う項目を別々に表示できます。
- 「予測区間 (10-90%) を表示」で、予測の幅を帯で表示します（共変量の方式によっては使えません）。
- 未来予測の結果は、CSV でダウンロードできます。

## TimesFM の予測パラメータ

| パラメータ | 初期値 | 内容 |
| --- | --- | --- |
| `max_context` | 1024 | 参照する過去の最大長（32 の倍数、最大 16384） |
| `normalize_inputs` | オン | 入力の正規化 |
| `use_continuous_quantile_head` | オン | 連続分位点ヘッド（予測区間に必要） |
| `force_flip_invariance` | オン | 反転不変性 |
| `infer_is_positive` | オン | 正値データで負の予測を防ぐ |
| `fix_quantile_crossing` | オン | 分位点の交差補正 |

## 説明変数（共変量）

### 追加できる説明変数

- **CSV の列**: 数値列は数値、文字列の列はカテゴリとして扱います。
- **日時から自動生成**: 曜日、平日/休日（日本の祝日を含めるかは選択可）、午前/午後、季節（4 季）、月（1〜12）。値が一定で意味を持たないもの（日次データの午前/午後など）は自動で除外します。

### 予測期間の説明変数が足りない場合（CSV の列）

CSV の列を使うには、予測期間の値が必要です。

- CSV の末尾に、予測項目が空欄で、説明変数だけ値が入っている行を付けると、その値を使います。
- 足りない分は、次のどちらかで埋めます。
  - **最後の値で埋める**（初期値）
  - **TimesFM で予測して埋める**（数値列のみ。文字列列は最後の値）。説明変数の予測が外れると、その誤差が予測結果に影響します。

### 共変量の方式

| 方式 | 内容 |
| --- | --- |
| TimesFM XReg（JAX 必須） | TimesFM 標準の共変量機能。`xreg_mode` と `ridge` を指定できます。 |
| Ridge 回帰＋TimesFM（JAX 不要） | 説明変数の効果を Ridge 回帰で取り除いた残差を TimesFM で予測し、効果を足し戻します。線形の関係のみ扱えます。 |

JAX を読み込めない環境では、初期値が自動で Ridge 方式になります。

検証期間の説明変数には CSV の実際の値を使うため、検証結果は「説明変数が正しく分かっている場合」の精度です。

## 設定の保存と読み込み

サイドバーの「設定の保存 / 読み込み」で、CSV 以外の設定（列の選択、期間、パラメータ、説明変数）を保存・読み込みできます。

- 「設定をダウンロード (JSON)」: JSON ファイルとして保存します。
- 「アプリのフォルダに保存 (settings.json)」/「settings.json を読込」: アプリのフォルダで保存・読み込みします。
- 設定ファイルを選び「選択した設定を適用」: 保存した JSON を反映します。

別の CSV に適用したとき、存在しない列は無視され、範囲外の値は範囲内に丸められます。グラフの表示設定は保存の対象外です。

## トラブルシューティング

### `DLL load failed ... アプリケーション制御ポリシーによってこのファイルがブロックされました`

Windows のアプリケーション制御（Smart App Control / WDAC / AppLocker）が、Python ライブラリの DLL の読み込みをブロックしています。次を試してください。

- `run.bat` を**管理者として実行**する。
- フォルダを `Downloads` の外（例: `C:\dev\timesfm_app`）に移し、`venv` を削除して `setup.bat` をやり直す。
- Smart App Control が原因なら、Windows セキュリティの設定を確認する（一度オフにすると、再インストールなしでは戻せません）。
- 会社・学校の PC で管理者が設定している場合は、管理者に相談する。

### `Failed to load the XReg module`

JAX が読み込めていません。共変量の方式を「Ridge 回帰＋TimesFM（JAX 不要）」に切り替えるか、原因を調べます。

```
venv\Scripts\activate
pip install "timesfm[xreg]"
python -c "import jax"
```

### 予測する項目が選べない

日時項目に数値列が選ばれていないか確認してください。「データプレビュー」で、列が正しく分かれているかも確認できます。

### 初回の予測に時間がかかる

モデルのダウンロードと読み込みが行われるためです。2 回目以降は速くなります。共変量の有無を切り替えると、モデルが再読み込みされます。

### GPU を使いたい

`pip` で入る PyTorch は CPU 版です。GPU を使う場合は、PyTorch 公式の手順で CUDA 版を `venv` に入れ直してください。
